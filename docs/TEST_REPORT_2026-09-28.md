## 默认间隔与响应头

| 项目 | 默认值 |
|---|---:|
| 首次静默阈值 `OPENCODE_CONN_SILENCE_MS` | 45 秒 |
| 静默重探 `OPENCODE_CONN_PROBE_INTERVAL_MS` | 60 秒 |
| 空闲重探 `OPENCODE_CONN_IDLE_PROBE_MS` | 60 秒 |
| 再次提示 `OPENCODE_CONN_RENOTIFY_MS` | 120 秒 |
| 探测超时 `OPENCODE_CONN_PROBE_TIMEOUT_MS` | 5 秒 |

首次空闲检查在配置后的下一周期发生。探测完成后间隔计时，同一端点的慢探测不重叠；默认调度精度约 1 秒，较短设置下最低 50 毫秒。环境变量随进程启动读取，修改后需重启。

HTTPS 建立 TLS 连接后，服务端发送响应状态和响应头；可以先发送头，也可以等正文开始才发送，代理还可能缓冲。`fetch()` 得到状态和头就能返回，正文仍可能等待或中途停顿。参见 [MDN 的响应处理说明](https://developer.mozilla.org/en-US/docs/Web/API/Fetch_API/Using_Fetch#handling_the_response)。本次受控流与真实 OpenCode 验收都覆盖头先到、正文后到的情形。
